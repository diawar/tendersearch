# Прямое получение медицинских закупок

Исследование 29.10.2026; прямой адаптер реализован 30.10.2026.

## Реализация

- `medical.py`: чтение публичного реестра, карточек, настоящих лотов,
  дополнительных описаний и документов MED/FMS. Отдельная анонимная сессия
  и CSRF для AJAX-чтения. Ключ Tenderbot не используется.
- `MedicalIndexedLot`: уникальность `(source, source_id)`, отдельная от индекса
  Госзакупа таблица. `MedicalIndex` хранит курсор страницы/объявления, аренду
  процесса, ошибки и время полного обхода. Миграция `0009`.
- Сервис Compose `medical-indexer` / команда `index_medical`: круглосуточно,
  с общим ограничением один запрос в секунду на площадку. После полного
  обхода пауза 15 минут; после ошибки повтор того же объявления через 5 минут.
  Загружаются опубликованные и принимающие заявки (коды источников 210/220)
  с неистёкшим сроком. FMS используется в обычном режиме реестра без
  отдельного флага `med_services`. Архив, дополнение заявок и другие стадии
  не объявляются полностью покрытыми.
- Флажок «Закупки по медицине» выключен по умолчанию. Включённый флажок
  ограничивает поиск прямыми MED/FMS; выключенный ищет также по Госзакупу.
  Значение сохраняется в подборках, отображается зелёной удаляемой плашкой.
- «Предмет закупки» выбирается радиокнопками: Все / Товары / Работы / Услуги.
  По умолчанию Все. Неуказанный предмет (пустое значение, код 0) проходит
  любой выбранный вариант, но не отменяет остальные фильтры и исключения.
  MED/FMS сохраняет вид из строки лота или карточки при очередном обходе;
  ранее загруженные записи без этого поля до обновления считаются неизвестными.
- Названия способов сопоставляются с общим справочником по точному имени,
  исходные числовые коды площадок не копируются. Неизвестное имя сохраняется
  отдельным пунктом справочника. Общая группа не означает одинаковых правил участия.
- Избранное, скачивание/очистка документов и ежедневное наблюдение за статусом
  используют исходную площадку объявления. Ссылки UI и Telegram ведут на MED/FMS.
- Дубликаты FMS из единого портала сопоставляются только при подтверждённом
  `system_id=7`, `announcement_external_id` и одинаковом номере лота.
  Совпадение числового ID на разных площадках не объединяет лоты.
- Полнота поиска/рассылки зависит от завершения первоначального обхода.
  Накопленные медицинские лоты доступны до его завершения с отметкой неполноты.

### Текущие ограничения

В проверенных подробностях MED/FMS адрес поставки возвращается текстом,
без структурированного КАТО. Такой лот не проходит фильтр области/города;
выдача с географическим фильтром помечается неполной с пояснением.
Юридический адрес заказчика не подставляется вместо места поставки.
Поиск в содержимом файлов и OCR этой интеграцией не добавляются:
поиск работает по названию и дополнительным описаниям, файлы скачиваются
при добавлении в избранное по общим правилам приложения.

Для HTTPS включена стандартная проверка цепочки. В пакет добавлен публичный
промежуточный сертификат GoGetSSL RSA DV SSL CA 2, отсутствующий в цепочке
сервера; он проверен системным X509Chain Windows. SHA1 thumbprint:
`3F3C45BB6A48088EB1D3B4EC366D9841AFFFCC38`. Это не ключ и не сертификат
пользователя. Проверка TLS не отключается.

## Вывод

Данные med.ecc.kz и fms.ecc.kz доступны напрямую: реестр объявлений,
карточки, таблицы лотов, подробности лота и публичные документы.
Проверенные запросы не потребовали учётной записи, ЭЦП или API-ключа.
Tenderbot не участвует в предлагаемой схеме загрузки.

Документированное внешнее REST/JSON API в просмотренных материалах не найдено.
Это не доказательство отсутствия закрытого интеграционного API.
Рабочий проверенный способ — GET публичных HTML-страниц и штатные AJAX-запросы
сайта. AJAX в проверенных обработчиках также возвращает HTML.

## Проверенные HTTP-запросы

Одинаковые маршруты на обоих хостах, язык `ru`:

| Назначение | Метод и путь | Результат |
|---|---|---|
| Реестр | `GET /ru/searchanno` | 10 объявлений на первой странице |
| Следующая страница | `GET /ru/searchanno?page=2` | Другие 10 объявлений |
| Поиск номера | `GET /ru/searchanno?numberAnno=<номер без суффикса>` | По одному нужному объявлению на проверенных примерах |
| Карточка | `GET /ru/announce/index/<announcement_id>` | Название, сроки, способ, заказчик, сумма |
| Лоты | `GET /ru/announce/index/<announcement_id>?tab=lots` | Таблица настоящих лотов с идентификаторами |
| Детали лота | `POST /ru/announce/ajax_load_lot/<announcement_id>` | HTML подробностей, form body `id=<lot_id>` |
| Разделы документов | `GET /ru/announce/index/<announcement_id>?tab=documents` | Перечень групп документов |
| Файлы группы | `GET /ru/announce/actionAjaxModalShowFiles/<announcement_id>/<group_id>` | HTML со ссылками на файлы |
| Скачивание | `GET /files/download_file/<id>/<id>/` | Проверено получение настоящего PDF |

Идентификаторы брать из реальных ссылок/атрибутов страницы, не вычислять.
Для POST сначала получить страницу с анонимной cookie-сессией, извлечь
`meta[name=ci_csrf_token]`, если он непустой — отправить как поле формы
`ci_csrf_token`; сохранить cookies, Referer и X-Requested-With.
На MED в проверенной странице значение токена пустое, на FMS непустое.
Секреты и значения токенов не записывать в логи.

Источники маршрутов: `/js/searchanno.js`, `/js/announce/view.js`,
`/js/announce/docs.js` и формы/ссылки публичных страниц.
Обработчики подписания, изменения закупок и подачи заявок не вызывались.

## Фильтры и различия

В HTML форм найдены `numberAnno`, `titleAnno`, `plan_amoun_start`,
`plan_amoun_end`, `methodz`, `statuses`, `date_start`, `date_end`, `kato`.
Поиск по номеру и пагинация проверены; точная семантика границ дат и остальных
фильтров ещё требует контрольных запросов.

MED дополнительно: `org_name`, `org_bin`, `point_types`, `type_trade`.
FMS: `bin_name`, `type`, `med_services`, `trd_buy_attrs`, `announce_years`.
Не считать все записи FMS лекарствами: площадка также содержит медицинские услуги.

Коды справочников отличаются от единого Госзакупа. Например, в формах MED/FMS:
`210` опубликовано, `220` приём заявок, `230` дополнение заявок;
MED: `54` тендер, `121` один источник, `3` запрос ценовых предложений.
FMS содержит также специальные способы закупок и логистику.
Нужна отдельная таблица соответствий, а не копирование наших числовых кодов.

## Исходные требования к подключению

1. Отдельные источники `med_ecc` и `fms_ecc`. Хранить исходный ID и номер;
   уникальность по `(источник, исходный ID лота)`. Существующий числовой ID
   Госзакупа нельзя использовать как общее пространство идентификаторов.
2. Собирать реестр, затем реальные лоты; загрузку подробностей и документов
   кешировать. Документы сохранять по действующим правилам избранного.
3. Сопоставлять объявления FMS с объединённым Госзакупом по исходной площадке
   и external ID. Одного совпадения номера недостаточно; номера разных
   площадок могут совпадать.
4. Искать по названиям и обоим описаниям. В контрольном MED-лоте подписи языков
   краткого описания не соответствуют языку текста: нельзя отбрасывать одно поле.
5. Разбирать таблицы по заголовкам, а не фиксированным позициям: MED и FMS,
   а также разные способы закупки имеют разные столбцы.
6. Небольшая частота запросов, повтор при временной ошибке, журнал полноты обхода.
   Не превращать ошибки загрузки/разбора в пустую успешно завершённую выдачу.
7. Флажок «Закупки по медицине» по умолчанию выключен; после подключения источника
   сохранять в подборках и показывать зелёную снимаемую плашку выбранных условий.
   До загрузки данных не выдавать флажок за работающий фильтр.

## TLS и ограничения проверки

PowerShell Invoke-WebRequest с обычной проверкой сертификатов Windows успешно
выполнил все контрольные запросы. Никакого отключения проверки сертификатов нет.
Ранее Python/httpx сообщал `unable to get local issuer certificate`.
Проверка HTTPS успешно выполнена и в действующем Docker/Linux с добавленным
промежуточным сертификатом. `verify=False` не используется.

Проверка выборочная: два объявления, страницы 1/2 реестров, детали двух лотов
и по одному PDF. Полнота всего архива, скорость массового обхода и гарантии
стабильности недокументированных обработчиков пока не подтверждены.
Прямой сбор запущен в приложении. Первоначальный полный обход контролируется
через MedicalIndex; до его завершения выдача обозначается неполной.

Исследовательские ответы и нормализованные примеры находятся в игнорируемой
папке `data/medical-direct/`; не включать сырые ответы, cookies и PDF в Git.
В tests/fixtures/medical включены только очищенные публичные таблицы
для регрессионных тестов, без сессий, токенов и скриптов.
