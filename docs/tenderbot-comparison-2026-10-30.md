## Подтверждённые недостатки текущего сбора

1. `collect_index_page()` обходит только реестр `/lots/`. Он получает полные карточки известных объявлений, но сохраняет только лоты, встреченные в реестре. Поэтому часть полученных из карточки лотов теряется. Объявления без единой строки в реестре вообще не обнаруживаются.
2. `extended_description()` добавляет `plan_items.extra_description*`, но пропускает `plan_items.description*` и названия позиций плана. Коврик 81641458-ЗЦП1 подтверждает значимость короткого описания.
3. Поиск по общему названию объявления у нас не включён. Добавлять его автоматически ради совпадения количества не следует: так сетевая карта и кресло начнут попадать по запросу «мыш».

## Порядок исправления

1. Дополнить поисковый текст названиями и короткими описаниями позиций плана. Обновить уже накопленный индекс из кеша карточек, не ожидая сетевого обхода и не создавая дубли текстов.
2. Добавить устойчивый обход реестра активных объявлений с загрузкой полного состава лотов. Одного сохранения соседних лотов в уже найденных карточках недостаточно: семь объявлений исходной проверки не имели ни одной строки в реестре лотов.
3. При сборке строки из карточки брать статус и идентификаторы лота из самого лота, сроки и способ — из соответствующего объявления. Проверять действующий срок, статус, признаки удаления; сохранять источник каждого поля. В исследованных ответах `announcement.system` нередко равен EPZ (4), тогда как соответствующие лоты маркированы ЭГЗ (1): нельзя молча перезаписывать систему лота системой объявления.
4. Дедуплицировать источник + ID и логическую идентичность лота существующим `lot_identity`. Не дублировать объединённый лот по числу позиций плана. Завершение цикла должно учитывать оба обхода, а очистка `current` — их объединение.
5. Повторить сравнение одновременно снятых выборок, отдельно указав способы 12/33, открытый/предстоящий приём, позиции/объединённые лоты и совпадения только в названии объявления.

В рамках этой проверки сборщик и прикладные записи не изменялись. Этот документ фиксирует завершённый разбор и требования к следующему исправлению.

## Реализация после согласования, 30 октября

Сборщик дополнен вторым обходом `/announcements/` со статусами 6/7/9 и неистёкшим сроком. Для каждого объявления загружается полный ответ `/announcements/{id}/lots/`, включая позиции, отсутствующие в `/lots/`. Оба реестра используют разбиение по срокам, перекрытие страниц и сохраняемый курсор. Старые незавершённые курсоры автоматически получают дополнительный этап. Завершение и исключение исчезнувших записей выполняются после обоих обходов, по объединению найденных лотов.

Карточки повторно используются только если получены в текущем цикле; остальные обновляются. Статус и площадка берутся из лота, даты и способ закупки — из объявления; заказчики, предмет закупки и КАТО восстанавливаются из позиций плана. Идентификаторы источника сохраняются, объединённые лоты не разбиваются на отдельные результаты. Постоянно пропускаемые недоступные лоты повторно не включаются. В поисковый текст добавлены названия и короткие описания позиций плана. Общее название объявления не добавлено в текст совпадения.

Проверены восстановление курсора после ошибки, обновление старого курсора, разбиение большого реестра, очистка только после обоих этапов, удалённые и неактивные лоты, повтор страницы без дублей и совместимость остальных фильтров. Полный новый обход выполняется фоновым сборщиком; наличие контрольных лотов само по себе не подтверждает завершение всей базы.
