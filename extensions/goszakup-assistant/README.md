# Тестовая сборка расширения Chrome

## Очередь черновиков (0.9.0)

В рабочем пространстве на этапе «Интересные лоты» отметьте до 20 лотов и нажмите «В очередь черновиков». Очередь хранится в приложении отдельно у каждого пользователя. Откройте её в том же Chrome, где установлено расширение. У каждого лота сохраните подготовку и отдельно подтвердите одинаковый товар для нескольких позиций, если это действительно так.

Нажмите «Передать в расширение» у одного лота, затем откройте расширение на появившейся вкладке Госзакупа и явно запустите заполнение. Страница очереди должна оставаться открытой: она получает прогресс расширения и сохраняет его в приложении. После успешного заполнения автоматически сохраняются номер заявки и подтверждение описания; отдельный файл отчёта не нужен. Затем передайте следующий лот. Это последовательные явные запуски, не автономная подача пакета заявок.

При ошибке причина остаётся в очереди. Задачи сохраняются после закрытия браузера; сессия и данные расширения — нет. При потере сессии проверьте существующий черновик перед повторным запуском; не считайте старую надпись «Заполняется» подтверждением фоновой работы. Удаление пункта очереди не удаляет заявку на портале. Для выполняющегося пункта сначала остановите расширение.

Расширение получает доступ только к странице очереди и подготовки на настроенном адресе приложения. Фоновых запросов с паролями или ЭЦП нет; цена, обеспечение, подписание и отправка остаются ручными.

## Статус в приложении (0.8.0)

После завершения заполнения отчёт отдельно подтверждает создание черновика и сохранение описания товара. Нажмите «Передать в приложение» и подтвердите аккаунт: номер, ссылка и отметка описания сохранятся у вашего лота. Повторная проверка только списка заявок не стирает подтверждение описания; другой номер черновика его сбрасывает.

После ручной отправки на портале откройте «Мои заявки» и проверьте статус расширением. Передача подтверждённого статуса «Подана» переводит ранний этап в «Подали заявку» во всех ваших подборках и включает проверку итогов по БИН. Сохранённая локальная цена блокируется, но не считается считанной ценой портала. Договор, поставка, оплата и архив не откатываются назад. Статусы «Проект», «Завершена» и неизвестное состояние сами по себе не подтверждают новую подачу и не переводят этап.

В одиночном режиме отчёт передаётся явной кнопкой. В режиме очереди открытая страница очереди автоматически сохраняет прогресс текущего черновика. Расширение не выполняет подписание и отправку заявки.

## Продолжение существующего черновика (0.7.1)

Ссылка Госзакупа с открытием в новой вкладке обрабатывается в текущей вкладке. Перед переходом проверяются объявление, номер заявки и этап 1–3. Цена, подписание и отправка остаются ручными.

## Подготовка без JSON (0.7.0)

Скачайте ZIP в настройках того приложения, с которым будете работать, и обновите расширение в Chrome. Перезагрузите страницу подготовки лота. Сохраните товарные данные и реквизиты, при необходимости подтвердите одинаковый товар для всех позиций, затем нажмите «Подготовить черновик». Расширение получит подготовку и откроет нужное объявление. На вкладке Госзакупа откройте расширение и нажмите верхнюю кнопку «Создать / продолжить черновик». Подписание, подача, обеспечение и цена остаются ручными.

Изменённую форму сначала нужно сохранить: передаётся сохранённая подготовка своего аккаунта. Пароли, ЭЦП и cookies расширению не передаются. Реквизиты не помещаются в ссылку. Подготовка хранится в памяти расширения до закрытия браузера. Старая неподтверждённая попытка создания блокирует замену подготовки до проверки на портале.

Прямая передача работает только на страницах `/lots/<id>/preparation/` разрешённого приложения. ZIP, скачанный с сервера, привязывает соединение к его HTTPS-адресу; локальная сборка поддерживает localhost:8000 и 127.0.0.1:8000. При смене адреса скачайте архив с нового адреса. Совпадение origin проверяется включая порт; вложенные окна и другие сайты не принимаются. Доступ к страницам Госзакупа остаётся через activeTab после явного открытия расширения. Широкого доступа ко всем сайтам нет.

Кнопка передачи не запускает заполнение и не создаёт черновик на портале автоматически. Если расширение не найдено, обновите его и страницу приложения. Ручной перенос через JSON остаётся доступен в дополнительном разделе.

Установка: chrome://extensions → Режим разработчика → Загрузить распакованное расширение → выбрать эту папку.

Откройте кабинет https://zakup.gov.kz/cabinet/ и самостоятельно войдите через ЭЦП. Откройте расширение и нажмите «Проверить форму». Результат содержит только названия видимых полей и кнопок, без значений, cookies, токенов или ключей. Передайте его агенту для уточнения поддержки формы.

После проверки сохраните подготовку в карточке интересного лота нашего ПО, скачайте свежий JSON и выберите его в расширении. Файл содержит реквизиты: храните его приватно. Подготовка и прогресс сохраняются в chrome.storage.session до закрытия браузера; кнопка очистки удаляет только данные расширения, не заявку на портале. Расширение не обрабатывает ЭЦП, не подписывает и не отправляет заявки. Отчёт передаётся только по кнопке «Передать в приложение» на явно указанный адрес.

## Черновик ЗЦП (0.5.0)

Откройте нужное объявление в авторизованном кабинете zakup.gov.kz и нажмите «Создать / продолжить черновик». Расширение проверяет БИН и объявление, выбирает точно совпавшие адрес и ИИК, переносит телефон и нажимает «Далее» для создания проекта заявки. Если уже есть черновик, используется продолжение; подтверждённый номер сохраняется. Затем добавляется только нужный лот и сохраняется описание товара. Данные уже заполненного описания автоматически не заменяются.

Для нескольких позиций плана одинаковый товар заполняется только после отдельного согласия «Один и тот же товар для всех позиций этого лота». Число полей на портале должно совпасть с подтверждённым числом позиций в JSON. Если позиции требуют разных товаров, заполняйте описание вручную.

Работа останавливается перед обеспечением, ценовым предложением, подписью и отправкой. Консорциумы и неоднозначные поля требуют ручного заполнения. Адрес и ИИК выбираются только при единственном точном совпадении; сокращённый адрес может потребовать ручного выбора. Расширение не выбирает первый вариант списка по умолчанию и не удаляет другие лоты из существующей заявки.

Закрытие popup не отменяет текущую обработку; «Остановить заполнение» запрещает следующие шаги, но текущий запрос уже мог сохраниться на портале. Не изменяйте форму параллельно. При потере связи прогресс сохраняется; если создание не подтвердилось, повторное создание блокируется. Откройте объявление заново и проверьте «Продолжить заявку» / «Мои заявки», затем продолжите найденный черновик. Непрерывная синхронизация и очередь при закрытом браузере не реализованы. После перезапуска браузера сначала проверьте существующие заявки на портале.

После подтверждения номера и добавления нужного лота отчёт «Черновик найден» можно передать в приложение. Это подтверждает существование черновика с лотом, а не готовность к подаче. Совместимость конкретной формы портала проверяется при первом реальном запуске; при изменённой разметке расширение останавливается с сообщением.


## Чтение статуса (0.4.0)

JSON подготовки не нужен: укажите в расширении БИН организации, полный номер объявления и лота из одной строки в «Моих заявках». Поля остаются только в памяти окна расширения. Загруженный JSON подготовки также заполняет эти поля; проверка использует текущие значения полей. «Завершена» возвращается как completed: это статус заявки, а не победа или проигрыш. Импорт отчёта не меняет этап работы в приложении.

Поддерживается список с раздельными таблицами заголовков и строк. Таблицы сопоставляются только внутри общего контейнера при однозначной структуре; неоднозначная разметка не подтверждает статус.

В «Моих заявках» найдите нужное объявление. Откройте расширение, укажите БИН и номера или загрузите файл подготовки, затем нажмите «Проверить статус». Сверяются БИН в шапке, номер объявления и лота в одной строке, статус заявки и ссылка на её карточку. При неоднозначности, фильтрах, пагинации или незнакомой разметке выводится unknown — это не отсутствие заявки. «Проект» распознаётся как draft, точные статусы «Подана/Подано/Заявка подана» — submitted. Кнопка «Скачать отчёт» сохраняет JSON без токенов и реквизитов. В приложении на странице подготовки выберите отчёт и нажмите «Обновить статус». Автоматическая отправка отчёта и постоянная фоновая синхронизация не реализованы. Сначала проверьте эту сборку на реальной странице: селекторы и вид ссылки могут отличаться, тогда потребуется адаптация. Не меняйте отчёт вручную.


## Передача в приложение без файла

Войдите в приложение заранее. После чтения статуса проверьте поле «Адрес нашего приложения» (для разработки — http://localhost:8000, для сервера — его HTTPS-адрес). Нажмите «Передать в приложение». В новой вкладке проверьте аккаунт, БИН, объявление и лот, затем подтвердите сохранение. Лот должен уже находиться в рабочем пространстве этого пользователя. Подготовку товара для чтения/сохранения статуса заполнять не требуется. Ссылка открывается с отчётом во фрагменте URL, который удаляется страницей при получении; на сервер отчёт отправляется обычным POST с CSRF-защитой и текущей сессией приложения. Расширение не получает пароль, токены или cookies приложения. Если сохранение не подтвердилось, не считайте статус переданным: повторите попытку. Скачивание отчёта файлом остаётся доступным. Фоновая синхронизация не реализована.

Реквизиты организации и телефон задаются в настройках приложения. Новая подготовка получает адрес, счёт и телефон; сохранённая подготовка лота сохраняет свои значения.

В версии 0.6.0 поддерживается текущая разметка Select портала. «Тип налогоплательщика» выбирается в настройках приложения из вариантов, показанных на Госзакупе, и передаётся в свежем JSON. Старая подготовка без этого поля получает значение из настроек при экспорте; уже сохранённое в подготовке значение сохраняется. На портале выбирается только единственное точное совпадение. Если поле отсутствует на портале, расширение не добавляет его; если в существующей заявке выбрано другое значение, обработка останавливается.

В версии 0.6.1 адрес, счёт и тип налогоплательщика сравниваются с вариантами открытого списка без вставки полной строки в поиск. Старый поисковый текст очищается. Адрес в настройках копируйте целиком из списка Госзакупа; совпадение проверяется с учётом регистра, пробелов и пунктуации, но слова и цифры должны совпадать.

В версии 0.6.2 исправлено подтверждение выбранного значения в стандартном одиночном Select портала: метка может быть текстом непосредственно внутри контейнера. Текст в поисковой строке без признака выбранного значения не считается подтверждением выбора.

В версии 0.6.3 БИН проверяется только в видимой шапке кабинета (header / banner / ant-layout-header). Повтор того же БИН допустим; БИН заказчика в содержимом страницы не участвует в проверке. Отсутствующая, неоднозначная или чужая организация в шапке останавливает заполнение. Проверка на странице с другим БИН вне шапки не может разрешить работу от чужой организации.

В версии 0.6.4 после перехода между шагами ожидается загрузка документов, данных нужного лота и формы описания. Номер черновика и состояние заполнения показываются отдельно: наличие черновика не означает, что описание товара сохранено.

В версии 0.6.5 записи плана из реестра отделены от полей заявления. Если API содержит несколько записей плана, а форма показывает один полный набор товара, изготовителя и страны для этого же лота, он заполняется при включённом согласии на одинаковый товар для всех позиций. Расхождение отражается в сообщении. Чужой лот, неполные наборы полей, дополнительные неожиданные наборы и отсутствие согласия по-прежнему останавливают обработку. Количество записей API не переписывается по предположению.


### 0.9.1 — восстановление после закрытия браузера
Минимальный журнал защиты от дублей (БИН, объявление, лот, номер черновика и неопределённая попытка создания) хранится локально между запусками Chrome. Реквизиты и описание остаются в памяти сессии. Очистка подготовки не снимает защиту от повторного создания. Если попытка не подтверждена, проверьте существующую заявку на портале. Экспорт приложения также передаёт ранее подтверждённый номер заявки.
