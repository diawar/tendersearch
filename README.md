# TenderSearch

Поиск закупок Казахстана: общая база активных лотов, поиск по названиям и дополнительным описаниям, персональные подборки, избранное и Telegram-уведомления.

Актуальные требования, архитектура и ограничения: [ТЗ для ИИ-агента](AI_AGENT_TECHNICAL_SPECIFICATION.md). `TECHNICAL_SPECIFICATION.md` и `docs/stage-*.md` отражают ранние этапы.

## Что работает

- Поиск по нескольким словам с И/ИЛИ, настройкой совпадения и исключениями.
- Флажок «Только с авансом» (по умолчанию выключен), сохранение в подборке и зелёная плашка выбранного условия. Признак определяется по положительному `prepayment` в пунктах плана или их `specifics`; неизвестное значение не считается подтверждённым авансом. При обновлении существующей установки выполните `docker compose run --rm --no-deps web python manage.py backfill_advance_flags`, чтобы заполнить признак из сохранённых ответов API без повторной загрузки.
- Фильтры статусов, способов закупки, суммы, сроков, области/города, БИН и номера.
- Личные подборки и избранное; таблица и карточки результатов.
- Круглосуточное накопление активных статусов источника 6/7/9 с неистёкшим сроком подачи, включая ожидающие начала приёма. Все способы закупки собираются независимо от фильтров пользователей.
- Поиск по накопленной базе без ограничения глубины в отдельной очереди.
- Telegram: проверки и рассылки подборок с 07:00 до 19:00 по Алматы; статусные уведомления и ручные действия — круглосуточно.
- Скачивание документов при добавлении в избранное; удаление файлов после удаления последнего связанного избранного.

Первоначальный сбор может занимать часы. Панель поиска показывает состояние базы и непроверенные описания. Неполный результат не доказывает отсутствия закупки на портале. Полный архив не загружается; физическая очистка старых записей пока не включена. Поиск внутри файлов и OCR ещё не реализованы.

Если карточка объявления возвращает HTTP 404, сборщик сохраняет лоты из реестра и продолжает обход. Их дополнительные описания отмечаются непроверенными и запрашиваются повторно позже; пока такие активные лоты остаются, полнота базы не подтверждается. Ошибка самого реестра, доступа, сети или формата ответа сохраняет курсор страницы для повторной попытки.

## Запуск на новом компьютере

Нужны Git, Python 3.11+ и Docker с Compose. На Windows — Docker Desktop с WSL 2.

```powershell
git clone https://github.com/diawar/tendersearch.git
cd tendersearch
python scripts/setup_local.py
docker compose up -d --build
docker compose exec web python manage.py sync_references
docker compose exec web python manage.py sync_cities
```

Приложение: [http://localhost:8000](http://localhost:8000).

`setup_local.py` создаёт `.env` со случайными секретами и `data/first-login.txt` с данными первого входа. Существующие настройки не перезаписываются. `initialize` применяет миграции и создаёт администратора, сохраняя пароль уже существующего пользователя.

Самостоятельная регистрация закрыта. Административный веб-интерфейс временно отключён; управление пользователями доступно через Django-команды администратора.

Это запуск с новой базой. Пользователи, подборки, избранное, Telegram-привязки и документы прежней установки требуют отдельного защищённого переноса PostgreSQL, тома документов и локальных настроек. В GitHub эти данные не включаются.

## Telegram

Создайте отдельного бота TenderSearch через @BotFather. Добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` в локальный `.env`, ориентируясь на `.env.example`, затем выполните:

```powershell
docker compose up -d web worker search-worker indexer telegram
```

Подключение пользователя выполняется через одноразовую ссылку в настройках приложения. Уведомления включаются отдельно для каждой подборки. Первый обход запоминает исходную выдачу без рассылки архивных объявлений.

## Службы и данные

| Служба | Назначение |
| --- | --- |
| `web` | Django, Gunicorn, HTMX, статические файлы |
| `search-worker` | Ручные поиски, очередь `interactive` |
| `worker` | Мониторинг, карточки и документы, очередь `celery` |
| `indexer` | Круглосуточное накопление базы |
| `telegram` | Планирование проверок и доставка уведомлений |
| `db`, `redis` | PostgreSQL 17 и Redis 7 |
| `initialize` | Миграции и первый администратор; завершение службы нормально |

Данные сохраняются в именованных томах Docker. Для обычной остановки и запуска:

```powershell
docker compose stop
docker compose start
docker compose ps -a
docker compose logs --tail 50 web indexer search-worker
```

`docker compose down -v` удаляет тома с данными, поэтому не используйте его для обычной остановки.

Пауза/продолжение загрузки с сохранением позиции:

```powershell
docker compose exec web python manage.py index_procurements --pause
docker compose exec web python manage.py index_procurements --resume
```

После изменений кода нужно пересобрать образ: исходники не подключены в контейнеры как редактируемый том.

```powershell
docker compose build web
docker compose run --rm --no-deps initialize
docker compose up -d
```

## Разработка и проверки

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
.\.venv\Scripts\python.exe -m pytest
docker compose exec web python manage.py check
docker compose exec web python manage.py test tender_search.core
```

Локальные Django-тесты без PostgreSQL:

```powershell
$env:TENDER_SQLITE = '1'
$env:DJANGO_SECRET_KEY = 'local-test-only-key'
.\.venv\Scripts\python.exe manage.py test tender_search.core
```

`scripts/verify_*.py` проверяют работающую установку; некоторые создают поиски и временное избранное. Изучите сценарий перед запуском на рабочих данных.

## Доступ и секреты

Веб-порт привязан к `127.0.0.1:8000`, PostgreSQL и Redis наружу не опубликованы. Для внешнего доступа нужны HTTPS и настройка доменов/CSRF. `compose.tunnel.yaml` задаёт дополнительную веб-службу; сам туннель и локальный `data/tunnel.env` настраиваются отдельно.

В Git не включаются `.env`, рабочие базы, дампы, содержимое `data/`, скачанные документы и временные исследования API. `.env.example` содержит только заглушки. Резервные копии пользовательских данных и секреты передаются отдельно в зашифрованном виде.

Приложение читает публичные данные `zakup.gov.kz`. Подача заявок, ЭЦП и NCALayer не автоматизируются. Перед участием проверяйте актуальные условия на государственном портале.
